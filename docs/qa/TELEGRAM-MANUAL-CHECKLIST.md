# Реальные Telegram-клиенты: компактная приёмка

Статус сценария: **PARTIAL** — открытие главного меню и один наблюдавшийся локальный бросок Telegram Desktop PASS; остальные реальные шаги NOT RUN/BLOCKED. Подготовка сценария и наличие клиента не являются PASS игры.

## Перед началом

Нужен разрешённый изолированный HTTPS-стенд с исполняемым кодом `a3279b0a1f1b697f8662a2b911eadd9dc9b92425` (или доказанно идентичными исходниками), тестовым ботом и отдельными тестовыми данными. Сопоставление URL, артефакта и SHA подтвердить манифестом стенда. Если версия/изоляция не подтверждены — **BLOCKED**, рабочий сервер для этого прогона не использовать. В финальном продолжении поднят отдельный локальный стенд; по разрешению владельца изменена только персональная menu-кнопка подтверждённого тестового бота. Production не менялся.

Использовать настоящий Telegram Desktop, Telegram Web с настоящей авторизованной сессией и Telegram на физических Android/iPhone. Browser viewport, Android Emulator, iOS Simulator и подставной WebApp SDK отмечаются отдельно и не заполняют эти строки PASS.

Нужны два разрешённых тестовых аккаунта; для сравнения прав — обычный игрок и владелец. Авторизацию пользователь выполняет самостоятельно. initData, сессии, числовые ID, токены и данные чужих чатов в отчёт не переносить.

### Проверка ресурсов финального этапа

Готовые runtime-архивы получены из существующего [CI-артефакта](https://github.com/zabbarov13-star/manager-game/actions/runs/45425055777/artifacts/14936019778), без сборки. Манифест содержит merge-коммит `92bced50a6c533e6773343f8aef053eaecc218f7`; его дерево `cad89ff49e90445e0f77dbc36f15392feb1282c4` равно дереву `a3279b0`. Проверены SHA-256 обоих архивов, отсутствие небезопасных tar-путей/ссылок, рабочих SQLite и `.env`. Кандидат запущен локально в новых каталогах, с отдельными пустыми SQLite и loopback-портами 18443/18444/18480. Отдельные переносимые Caddy и cloudflared публикуют временный HTTPS-origin. Это тестовый запуск, не развёртывание на VPS.

Внешний HTTPS проверен с обычной проверкой сертификата: без частного ключа 403, с ключом provenance и health 200, внутренние маршруты 404. `roomsEnabled=false`, Stars/AdsGram выключены. Ключ не опубликован: ссылка находится только в локальном `release-output/final-acceptance/stand/private/access.json`. Origin живёт только пока работают записанные процессы туннеля/стенда.

Bot API подтвердил `@ManagerGameTestBot` в обычной API-среде. По явному разрешению изменена только menu-кнопка личного чата настроенного тестового владельца: «Тест a3279b0». Глобальное меню осталось прежним, readback совпал. Прежнее значение сохранено приватно; локальный `restore_test_menu.py` восстанавливает только эту кнопку. `/start`, webhook, polling, токены не менялись. Старую глобальную кнопку на VPS для приёмки не использовать.

### Шаблон отдельного Linux-стенда — справка для будущего переноса

Использовать **другой, явно разрешённый тестовый хост**, не VPS `95.181.169.84`. Существующие `telegram/staging/compose.yaml` и `Caddyfile` рассчитаны на отдельный хост, собирают образ из исходников и занимают 80/443. Их нельзя применять на production или запускать здесь как готовый кандидат. Для уже собранных архивов ниже описан вариант без повторной сборки и без Docker.

| Роль | Частная конфигурация только нового стенда |
|---|---|
| Общий каталог | Новый `/srv/manager-acceptance-a327`; архивы распаковать в разные новые `rooms-runtime` и `adapter-runtime`; данные — только в новом `data`, права оператора теста |
| Rooms | `PORT=18480`, `ROOM_BIND=127.0.0.1`, `ROOM_DATABASE=/srv/manager-acceptance-a327/data/rooms.sqlite`, `ROOM_ALLOWED_ORIGINS=https://<ОТДЕЛЬНЫЙ-ТЕСТОВЫЙ-ДОМЕН>`, `ROOM_EXTENSION=telegram`, `ROOM_TRUST_PROXY=1` |
| Подписанная проверка прав | Rooms: `COSMETIC_RPC_ENDPOINT=http://127.0.0.1:18444`; в обоих процессах одинаковый **новый** частный `COSMETIC_RPC_SECRET` не короче 32 символов |
| Adapter | `TELEGRAM_MODE=adapter`, `BIND=127.0.0.1`, `PORT=18443`, `COSMETIC_RPC_PORT=18444`, `PUBLIC_ORIGIN=https://<ОТДЕЛЬНЫЙ-ТЕСТОВЫЙ-ДОМЕН>`, `TELEGRAM_DATABASE=/srv/manager-acceptance-a327/data/telegram.sqlite` |
| Telegram | Отдельный разрешённый токен и новый webhook secret; для обычной Bot API-среды `TELEGRAM_ENV=production` — это имя API-режима, а не разрешение использовать production-инфраструктуру. OWNER_TELEGRAM_ID задать приватно; не копировать production `.env` |
| Монетизация | Обязательно `STARS_ENABLED=0`, `ADS_VERIFIED_GATEWAY_ENABLED=0`; Block ID не задавать; счета и рекламные показы не запускать |
| TLS-прокси | Только на отдельном хосте: `/api/rooms` и `/api/rooms/*` → `127.0.0.1:18480`; остальное публичное приложение → `127.0.0.1:18443`. `/internal`, `/internal/*`, `/ads/verified-receipt`, `/telegram/webhook` → 404. Порт 18444 не публиковать |

Порядок после предоставления ресурса и явного допуска:

1. Проверить SHA256SUMS пакета и манифест; убедиться, что каталог/хост новые и не содержат рабочих данных. Распаковать два архива раздельно, не копируя существующие базы.
2. В частных отдельных env-файлах заполнить значения таблицы; проверить Node.js 24, свободность выбранных портов и права новых каталогов. Секреты не переносить в GitHub.
3. Из корня `rooms-runtime` запустить существующий `online/server.cjs` через Node 24 с его частным env-файлом; из `adapter-runtime` — `telegram/server.cjs` со вторым env-файлом. Не запускать poller и не регистрировать webhook. Исходники и зависимости не пересобирать/переустанавливать.
4. В отдельном прокси с новым тестовым доменом настроить указанные маршруты, проверить конфигурацию его собственным валидатором и доверенный внешний HTTPS. Рабочий Caddy не трогать. Этот Linux-шаблон не применялся; текущий стенд работает локально на Windows в отдельных каталогах и процессах.
5. Зафиксировать манифест кандидата, новые пути SQLite, loopback-порты, отсутствие общих volumes/служб и подтверждённую привязку отдельного бота. Только после этого переходить к игровому кругу ниже.

`/start` остаётся BLOCKED: его обработчик менять не разрешено. Для текущей приёмки использовать только персональную кнопку «Тест a3279b0». Смена меню сама по себе не подтверждает запуск Mini App и Telegram-авторизацию.

Откат тестового стенда: остановить только его процессы и вернуть предыдущий **тестовый** каталог кода. Production, службы и базы не затрагивать; не затирать новые сохранения старой копией автоматически. Удалять можно лишь специально созданные тестовые данные после проверки их принадлежности стенду и отдельного разрешения на удаление.

## Один круг на каждом клиенте

| № | Действия | Ожидаемый результат |
|---|---|---|
| 1 | Открыть Mini App из тестового бота, затем закрыть и открыть повторно | Проверенный стенд, главное меню, корректный русский интерфейс; вход без зависания |
| 2 | Открыть настройки, правила, магазин и вернуться | Доступные кнопки, читаемый текст, сохранённые настройки; нет наложений и обрезания safe areas |
| 3 | Обычным аккаунтом рассмотреть 12 премиальных героев, портреты и анимации; вернуться к выбору | Изображения и реакции видимы; предпросмотр не выдаёт игровое право |
| 4 | Сравнить обычный аккаунт и владельца | Закрытый контент остаётся закрытым у обычного; владельцу доступна косметика без предложения оплатить уже доступное |
| 5 | Начать тестовую партию, бросить, купить игровое владение; проверить карточку и «Отдых» | По одному действию на нажатие; допустимые фазы; правильные вкладки; «Отдых» открывает обзор без изменения денег |
| 6 | Масштабировать поле, вручную сдвинуть камеру, дождаться автоматического движения | Читаемые клетки и карточки, устойчивые позиции фишек, камера уважает ручное управление |
| 7 | Продолжить после закрытия Mini App и перезапуска Telegram | Тестовая партия, выбор и доступные права восстановлены; нет повторного исполнения прежнего броска/покупки |
| 8 | Создать сетевую тестовую комнату и подключить второй реальный клиент; выполнить по ходу каждым | Совпадают поле, деньги, собственность и персонажи; кубики принадлежат бросающему; в существующем режиме PeerJS используется внешний сигналинг |
| 9 | Отправить сообщение в чат тестовой комнаты, открыть/закрыть клавиатуру, сменить размер окна/ориентацию | У другого участника появляется непрочитанное уведомление; ввод не перекрыт; после чтения индикатор снимается |
| 10 | Свернуть Telegram и вернуться; на физическом телефоне сменить Wi-Fi/мобильную сеть; восстановить соединение хоста | Анимации приостановлены в фоне; состояние согласовано после возврата; нет повторных ходов и проигрывания старых событий |
| 11 | Включить reduced motion системными средствами, проверить движение и результат партии | Нет непрерывных эффектов; игра и результаты работают; победа/поражение корректно показаны |

Шаги, требующие двух устройств/аккаунтов, не подменять двумя контекстами одного браузера. Создание/использование тестовых комнат допускается только после подтверждения изоляции стенда. Не создавать счета, не подтверждать платежи/возвраты, не запускать AdsGram и не изменять реальные права или базы. Финансовые и рекламные сценарии требуют отдельной разрешённой приёмки.

## Запись результата

Для каждого клиента записать: платформа, фактическая версия Telegram/ОС, физическое устройство либо Desktop/Web, SHA/артефакт стенда, дата, номер шага, PASS/FAIL/BLOCKED и краткое обезличенное наблюдение. Для шага 3 отмечать просмотренных героев и состояния; непроверенные сочетания не считать пройденными. Скриншот при необходимости ограничивать Mini App и обезличивать.

| Клиент | Фактический игровой прогон | Причина |
|---|---|---|
| Telegram Desktop / Windows | PARTIAL | После ручного клика открыто главное меню Mini App; origin стенда совпал. Затем пользователь сделал ход: UIA наблюдал 2 + 3 = 5 и фазу покупки. Продолжение BLOCKED: клики без геометрии, клавиатура не переводит фокус в WebView |
| Telegram Web | BLOCKED / NOT RUN | Авторизованная Web-сессия не подтверждена; доступный browser backend не содержит Telegram Web, поиск нативных вкладок не дал надёжного результата |
| Telegram / физический Android | BLOCKED / NOT RUN | ADB devices: 0 authorized / 0 unauthorized / 0 offline |
| Telegram / физический iPhone | BLOCKED / NOT RUN | Доступность не подтверждена; поиск устройства по указанию пользователя не выполнялся |

## Автоматизация

Подтверждено на Windows: установленный Telegram Desktop запускается, предоставляет целевое окно и дерево доступности UIA через `computer-use`. Данные чатов и авторизации не экспортировались. После предоставления проверенного стенда можно автоматизировать навигацию и обезличенную фиксацию результатов в настоящем клиенте. Наличие UIA не гарантирует доступность каждого элемента встроенного WebView; это проверяется на стенде.

Переносимые официальные Android Platform Tools скачаны с проверкой контрольной суммы поставщика. `adb devices -l` выполнен на отдельном серверном порту 15037: 0 подключённых, 0 unauthorized, 0 offline. Затем остановлен только этот новый ADB-сервер. Физический Android не проверен. Для продолжения: подключить USB с передачей данных, включить отладку USB, самостоятельно разрешить компьютер на телефоне и выполнить шаги 1–11 в Telegram через тестовую кнопку. Серийные номера не публиковать. iPhone не искался.

Telegram Web: использовать только уже авторизованную разрешённую сессию; новая авторизация, пароли и коды не запрашивались. Второй разрешённый аккаунт не подтверждён: двухпользовательская партия и проверка обычного аккаунта остаются BLOCKED. Пользователю достаточно открыть тестового бота разрешённым вторым аккаунтом на отдельно согласованном тестовом маршруте; глобальное меню самостоятельно не менять.

Текущие Simulator/Emulator и Playwright результаты переиспользованы только в своих категориях; реальной Telegram-приёмкой они не считаются.


Продолжение от 25 ноября: дополнительных ручных действий у пользователя не запрашивали. Доступные шаги выполнены автономно на распакованном кандидате с синтетическим SDK: 7 PASS / 0 FAIL, [результаты и границы](POST-STAGE1-ACCEPTANCE.md).
