# Аудит PR №5 перед выпуском

Дата: 18.11.2026. Проверен фактический код `89773cf`, а не только описание PR.

Подтверждённые недостатки исходного PR:

1. Проверка 108 анимаций сравнивала два кадра; полный playback, длительность, фон и reduced motion проверены не для всех сочетаний. Реакции расхода/поражения сохраняли некоторые положительные эффекты; произвольный горизонтальный разрез спрайта способен давать шов.
2. Внешний PeerJS не проверялся: тест подменял сигналинг локальным SDP. Тесты не подтверждали покупку обоими участниками и настоящий разрыв канала.
3. Bot API всегда production; официальная тестовая среда не поддерживалась. SUPPORT_CONTACT мог отсутствовать при создании счёта. Публичный health сообщал starsConfigured без проверки готовности магазина.
4. Регрессионный тест сравнивал две производные сборки между собой, но не имел независимой контрольной сигнатуры стабильной 0.19.1. Добавлена такая сигнатура с явным учётом двух прежних адаптаций release-сборщика: ID мест и текста ошибки строительства.
5. Контроллеры имели анонимные visibility listeners без удаления при destroy; Контроллер анимации отдельно не учитывал Telegram activated/deactivated, хотя основной клиент уже сохранял игру/звук. Предпросмотр мог продолжать работу вне активного Mini App.
6. Есть резервирование одной базы, но отсутствовали единый проверяемый снимок двух баз, безопасная процедура восстановления и подготовленный отдельный тестовый HTTPS-стенд.

7. Запоздалый refresh профиля мог отменить новый выбор; общий минутный лимит API конфликтовал с длительным опросом комнат. Исправлены порядок ответов и разделение бюджетов без ослабления исходных лимитов комнат.
8. Права на образ проверялись при входе, но не повторно перед стартом после ожидания в лобби. Добавлена перепроверка действующего права; просроченный admission ticket владельца не равен утрате постоянного права.

9. Импорт локального сохранения в уже открытой странице не сбрасывал snapshot анимаций прежней партии. Добавлен новый baseline без воспроизведения старых игровых событий; первый новый ход сравнивается с импортированным состоянием.

Уже реализовано и сохраняется: серверная HMAC-авторизация, роль owner по числовому ID, 6 бесплатных/12 премиальных персонажей, цены, SQLite-покупки/возвраты, журнал финансов, aliases, подтверждённые события, дедупликация, watermark, исходные правила и кубики. Изменения только в Telegram-слое.

Внешние зависимости:

Уточнение инфраструктуры владельцем: найдены `manager-online.service`, `/opt/manager-online/current`, выделенный Node 24.22.2 и `/var/lib/manager-online/rooms.sqlite` на 8080. Общий сервер должен обслуживать APK/Telegram; автономный Telegram-режим создаёт отдельные комнаты; для этого VPS реализован adapter-only и расширение единственного сервера 8080. Конкретный план, проверка совместимости и ограничения — `deploy/SHARED-SERVER-PLAN.md`. Перезапуски/изменения VPS не выполнялись.

- BLOCKED: @ManagerGameTestBot и токен уже подготовлены локально; getMe в обеих средах завершился TIMEOUT. Требуется подтвердить личность и Telegram-среду, webhook и Main Mini App. Секреты не публикуются.
- BLOCKED: SSH root отклонён. На существующем HTTPS-origin найден первоначальный клиент «Менеджера»; владелец сообщил каталог/службу/БД, но фактические хеши и восстановление копии здесь не проверены. Новый сервер комнат не создаётся. Подробные факты и план — deploy/ACCESS-STATUS.md и deploy/README.md. Изменения VPS только после согласования.
- BLOCKED: кабинет AdsGram, Test Platform/Block ID, официальный доверенный контракт серверного подтверждения с уникальным событием и защитой подлинности. Доступный userId-only callback и browser show() не заменяют этот контракт.
- BLOCKED: физические Android/iOS и разрешение на реальные финансовые операции. Автоматизация не выдаётся за такую приёмку.

Итоговые PASS/FAIL/BLOCKED, доказательства и действия владельца дополняются по мере выполнения в `RELEASE-ACCEPTANCE.md`.

10. Исправлено дублирование комнат в целевой архитектуре: adapter-only без room DB, общий server extension с HMAC RPC до очереди/SQLite lock и проверкой revision. Replay сохраняет исходные signature/body; восстановление и откат проверены с замороженным исходным server.cjs (fddd6d5), а не только двумя версиями engine. Подробности deploy/SHARED-DEPLOYMENT.md.
