## Контракт и игра

`animation/core.ts`: discriminated union, строгая runtime-валидация обязательных и лишних полей. Local UI события не имеют sequence/игровых параметров и не отправляются другим участникам. Игровые события содержат sequence; параметры кубиков, объекта, суммы и хода берутся из подтверждённого состояния и журнала. Валидатор проверяет привязку game/player/character и известные клетки. Отсутствующие значения не подставляются.

Диспетчер ведёт ограниченную дедупликацию, watermark, очередь по игроку и приоритеты. Покупка отменяет менее важную реакцию, финал очищает очередь, последующее ожидание не вытесняет финал. Неизвестные типы/версии пропускаются. При восстановлении сохранения задаётся baseline без проигрывания прошлых действий. Спрайты и реквизит используют Canvas 2D; правило, баланс, исходные анимации кубиков и поток ввода не менялись.

Проверки: 32 теста Telegram/сети и 8 исходных проверок кубиков, строительства и комнат прошли; TypeScript strict/noEmit прошёл. Тесты подтверждают фактические значения кубиков, покупку после buy (без дублирования расходом), отсутствие покупки после decline, суммы журнала и победу только в финальном состоянии. Исходные `index.html`, `online/`, Android и Windows не изменены.

## Два участника и восстановление

`tests/animation-multiplayer.cjs` запускает два изолированных Chrome-контекста и настоящий локальный WebRTC data channel. Используются оригинальные P2PNetwork, P2PAuthority, checksum и фрагментация. Только SDP обменивается тестовым раннером, без публичного сигналинга. Проверены:

- подтверждение премиального образа обоих участников серверными билетами;
- одинаковые ID, sequence, время и параметры события dice.rolled у обоих участников;
- одинаковое потребление transition двумя контроллерами;
- повтор команды без второго броска;
- восстановление хоста из checkpoint и сохранение состояния;
- reconnect baseline без повторных эффектов;
- отказ поддельному билету и клиентскому telegramCharacterVerified;
- HTTP-путь: внутренний на вид заголовок клиента также не даёт доступ.

Внешний PeerJS-сервер не менялся и теперь проверен живым тестом: QA_EXTERNAL_PEER=1 использует настоящий внешний сигналинг и проверяет покупку обоими участниками, разрыв канала и восстановление. Обезличенный результат — qa-results/multiplayer-external.json. TURN не проверялся. Тест не моделирует разрыв мобильной сети или фон Telegram на телефоне. Старые клиенты получают базовую фигурку; метаданные необязательны и игровая схема прежняя.

## Владение, Stars и реклама

Роль владельца вычисляется только сервером по проверенному Telegram ID и OWNER_TELEGRAM_ID. Указанный пользователем ID находится в локальном игнорируемом `.env`; публичные конфиги содержат пустую переменную. На целевом сервере она ещё должна быть настроена. Тестовые аккаунты используют другие ID. Проверены owner/player, подмена initData, одинаковый username, подмена полей роли, восстановление роли новой сессией, доступ к будущему зарегистрированному косметическому товару. Владелец не получает фиктивные orders, grants или рекламные просмотры. Предпросмотр не выдаёт права.

Stars: проверены подпись webhook, XTR/сумма/аккаунт, повтор сообщения, восстановление и refund. Исторические права заменённых слотов разрешаются через aliases без переписывания заказов. Цены прежние: 10/25/15/20/39/39 Stars. Реальные списания и возвраты не выполнялись.

AdsGram остаётся OFF. Клиентский результат рекламы и userId-only callback не считаются доказательством. Нужен доверенный источник уникальных серверных событий и адаптер провайдера. Внутренний HMAC-контракт уже проверяет receipt, replay, 3 просмотра, +24 часа, максимум 72 и сброс в 00:00 МСК; эти тесты не означают подключение реального AdsGram.

## Повторение

Из `telegram/`: `npm install`, `npx playwright install chromium`, `npx tsc -p tsconfig.json`.
Из корня:

```sh
node telegram/build.cjs
node telegram/staging/init-local.cjs
node --test telegram/tests/*.test.cjs tests/p2p-routing-baseline.cjs
node --require ./telegram/tests/release-preload.cjs --test packaging/test-dice.cjs online/construction.test.cjs online/public.test.cjs
node telegram/animation/build-demo.cjs
node telegram/tests/animation-visual.cjs
node telegram/tests/animation-playback.cjs
node telegram/tests/browser-smoke.cjs
node telegram/tests/character-field.cjs
node telegram/tests/animation-multiplayer.cjs
```

Для установленного Chrome задать QA_CHROME. Галерея уже включена в PR; её генератор требует исходные выбранные карточки из пользовательского архива, которые целиком в Git не публикуются. Генератор WebP требует локальный JSON путей к исходным PNG; промпты и хеши исходников опубликованы отдельно. CI использует готовые ассеты и повторяет проверки без генерации изображений.

Дополнительно выполнен полный playback 108 событий с rAF и отдельными временными срезами тела и реквизита, измерением длительности и отмены. Reduced motion и 30 lifecycle-пересозданий проверены отдельно. Убран произвольный разрез спрайтов, потеря денег и поражение имеют отдельную постановку, повторная нарисованная маска/клавиатура хакера убрана. Подробности и границы измерений — qa-results/playback.json и RELEASE-ACCEPTANCE.md.
