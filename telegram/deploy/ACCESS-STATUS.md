Это результаты чтения, **не отчёт о развёртывании**. Сервер, бот, платежи и «Смайлокрут» не изменялись.

1. **Где найден «Менеджер».** Публичный клиент найден на `https://95-181-169-84.sslip.io/`: HTTP 200, заголовок «Менеджер — Назад в прошлое · тест онлайн». Каталог, контейнер, служба, владелец порта 8080 и расположение данных пока неизвестны. SSH `root@95.181.169.84`, порт 22, BatchMode/проверка известного host key: `Permission denied (publickey,password)`.
2. **Версия.** В HTML указана 0.19.0; сигнатура правил совпала с независимой стабильной 0.19.1 после двух известных нормализаций release-сборщика. Это подтверждает клиентскую механику, но не версию серверного процесса. SHA-256 HTML: `45544e405aed23de57eb221f904b1f5173f32b82505580ffa3d150640f29a561`.
3. **Данные для сохранения.** Сначала установить фактические bind mounts/volumes, конфигурации и схему старой установки. Сохранить все её данные, включая базы, WAL/SHM, профили, покупки/возвраты, сохранения, XP, достижения и рейтинги, если они есть. Наличие этих полей в старом сервере не подтверждено. Сохранения браузера/IndexedDB/localStorage требуют отдельного экспорта; копия VPS их не включает. При смене origin они автоматически не переносятся.
4. **Что требуется для обновления.** Приватный root/sudo inventory; привязка публичного сайта к конкретному процессу; проверка Node/SQLite и схем старых данных; проверяемая копия и восстановление в отдельный каталог; согласование конкретного плана. Неизвестная старая установка не принимается автоматически под управление нового скрипта. Текущий HTTPS `/health` отвечает 200 `{"ok":true}`; это не health новой Mini App.
5. **Риски.** Общий Caddy/80/443, неизвестное назначение 8080, ресурсы сборки, старые данные и service worker, смена origin, Node 18 на хосте против Node 24/native SQLite приложения. Общий Node обновлять не требуется: приложение подготовлено для изолированного Node 24 контейнера, инструменты инвентаризации совместимы с Node 18. Порт 8443 ещё не проверен на VPS. Новый поддомен при запросе `/health` вернул TLS `ERR_SSL_TLSV1_ALERT_INTERNAL_ERROR`; HTTPS там не подтверждён.
6. **Что сделано автономно.** Подготовлены приватная инвентаризация, диагностика бота без изменений, упаковка только коммитов, отдельная копия env, ограниченный Compose без второго Caddy, план с проверкой fingerprint, резервирование/проверка восстановления для распознанной установки и откат только кода. Приложение и порт 18080 скриптом не останавливаются. Реальный запуск/откат на VPS не выполнен.

## Бот и монетизация

- Локальный `.env` уже содержит токен, контакт поддержки и серверные секреты; значения не публикуются. Называть токен отсутствующим больше нельзя.
- Read-only `getMe` в настроенной тестовой и обычной среде Telegram завершился `TIMEOUT`, а не HTTP 401. Личность бота, webhook, меню и Main Mini App остаются **BLOCKED**, токен не объявляется недействительным. `TELEGRAM_ENV=test` пока не подтверждён: слово Test в имени бота не означает отдельную тестовую сеть Telegram.
- Stars backend проверен fixture-тестами. Живой официальный тестовый цикл и вывод через Fragment не проверены. В подготовленном развёртывании Stars OFF до отдельной проверки и разрешения.
- AdsGram OFF: нет подтверждённого доверенного источника уникального серверного события, кабинета и Block ID. `show()`/userId-only callback не принимаются за доказательство.

## Следующие действия

1. Предоставить имя существующего SSH-пользователя с sudo и путь к локальному ключу либо настроить ssh-agent. Содержимое ключа и пароли в чат не отправлять. Альтернатива — выполнить только inventory из README и передать приватный отчёт.
2. По инвентаризации уточнить исходный каталог/данные и сохранить прежний origin, если пригоден. Подготовить адресный план миграции старой установки; не создавать фиктивный managed-marker.
3. Согласовать план **до изменений VPS**, включая проверяемую копию, время остановки только «Менеджера», ресурсы сборки и изменение только его маршрута Caddy. Новый поддомен использовать лишь с обоснованием.
4. После подтверждённого HTTPS проверить бота из сети VPS. Только после подтверждения его личности/среды отдельно согласовать webhook/меню; Main Mini App настроить в BotFather. Затем пройти тестовые Stars и ручную приёмку устройств.

PR №5 не слит. Старый клиент остаётся доступным. Отсутствие SSH не заменено утверждением об успешной установке.
