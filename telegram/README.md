# Telegram Mini App «Менеджер»

Изолированная реализация поверх стабильного **v0.19.1**, коммит `ffa7f151874648ddf159c8a321827a4abe75ae00`. Код исходной игры, нативных оболочек, обычной веб-версии и PeerJS-сервера не изменён. Новые файлы находятся в `telegram/`, отдельная проверка — в `.github/workflows/telegram-mini-app.yml`.

**Статус: сборка и локальные проверки готовы; production не развёрнут.** Реальная авторизация, реклама и платежи требуют подключения владельцем. AdsGram намеренно отключён до появления надёжной серверной проверки события. Это не готовый к монетизации production-релиз.

## Что реализовано

- Исходные поле, графика, музыка, правила, броски и режимы. Telegram-сборщик запускает оригинальный сборщик в изолированной папке, нормализуя CRLF в LF. Это устраняет Windows-ошибку его точных текстовых шаблонов. Движок не переписывается.
- 6 исходных бесплатных персонажей: **Кассета, Ролик, Кадр, Радио, Руслан, Адель**. В оригинале Адель уже входит в первые четыре, поэтому первые четыре Telegram-списка составлены из остальных простых людей без дублирования. Порядок оригинальной версии сохранён в исходниках.
- 12 оригинальных премиальных персонажей: Мира, Тимур, Луна, Феликс; Ася, Оскар, Белла, Марсель; Акира, Хана, Рэн, Юки. Портреты и спрайты WebP с альфа-каналом. Изображения созданы встроенным `image_gen`; промпты — `assets/generation.json`, готовые файлы — `assets/`.
- У всех 18 есть биографии, черты характера и пять уникальных декоративных характеристик. Пять состояний отображения реализованы CSS-анимациями; это не покадровая анимация лиц. Реакции подключены к изменению баланса и исходу партии без влияния на механику.
- Один бесплатный стиль `heritage`; четыре исходных дополнительных стиля. Нефритовые кубики и сияние фигурки добавлены как отдельная косметика.
- Цены: персонаж 10 XTR, кубики 15, стиль 20, четыре фиксированных набора по три персонажа 25, все четыре стиля 39, комплект «Нефритовые кубики + Сияние фигурки» 39. Будущие товары не включены. Наборы с уже купленными предметами не продаются.
- Серверная HMAC-проверка Telegram `initData`, срок авторизации, привязка покупок и настроек к Telegram ID. Локальные партии имеют отдельный префикс хранения для каждого аккаунта; старые сохранения не импортируются и не перезаписываются.
- SQLite WAL: профиль, основания доступа, рекламные намерения, подтверждения, заказы, платежи, возвраты, обработанные Telegram updates. Выдача и суточный лимит — в `BEGIN IMMEDIATE`.
- Три награды в сутки, сброс в 00:00 МСК; продление на 24 часа с потолком 72 часа; при возврате Stars независимый рекламный доступ сохраняется.
- Официальные `createInvoiceLink`, XTR, проверка `pre_checkout_query`, выдача только по `successful_payment`, отзыв основания по `refunded_payment`. Клиентское `openInvoice: paid` само по себе ничего не выдаёт. `/paysupport` использует `SUPPORT_CONTACT`.
- Безопасные области Telegram, сворачивание/возвращение, адаптация мобильного заголовка, добровольная реклама, обработка ошибок без выдачи награды.

## Сеть и премиальные образы

PeerJS использует исходные идентификаторы, сервер `manager-peer-server.onrender.com` и исходный протокол. Дополнительно Telegram-сервис подключает неизменённый сервер комнат из `online/server.cjs` к отдельной базе комнат. Покупки хранятся отдельно от комнат.

Премиальный образ — локальная косметическая оболочка над одной из шести исходных фигурок. Это сохраняет совместимость протокола; старый клиент соперника показывает исходную фигурку. **Передача премиальных образов другим Telegram-клиентам пока не реализована.** Для неё потребуется отдельно согласованное расширение метаданных с обратной совместимостью. Характеристики не передаются в движок.

В локальной партии образ фиксируется при старте и сохраняется с ней. Истечение доступа не прерывает эту партию; новая партия проверяет доступ заново. Для сетевой игры ещё необходима проверка срока доступа на реальных клиентах при повторном подключении.

## AdsGram: обязательное ограничение

В [документации AdsGram Reward URL](https://docs.adsgram.ai/publisher/get-block-id) описан GET callback с подстановкой `[userId]`. Подтверждение браузерного `show()` не считается серверным доказательством. Документированный callback не даёт уникального ID просмотра и подписи, достаточных для заявленной защиты от повторной выдачи между последовательными просмотрами.

Поэтому `ADS_VERIFIED_GATEWAY_ENABLED=0` по умолчанию. SDK загружается только по добровольному действию после включения интеграции. **Нельзя просто включить флаг и считать AdsGram подключённым.** Владелец должен получить от провайдера проверяемый источник уникальных событий и реализовать доверенный адаптер. Адаптер в этот проект не входит, поскольку его реализация зависит от недокументированных возможностей/соглашения провайдера.

Подготовленный внутренний endpoint адаптера: `POST /ads/verified-receipt`. Это **не нативный webhook AdsGram**. Тело: `receiptId` (уникальный), `intentId`, `userId`, `itemId`, `completedAt` (Unix ms). Заголовки: `X-Receipt-Timestamp` (Unix ms), `X-Receipt-Signature = HMAC-SHA256(ADS_RECEIPT_SECRET, timestamp + '.' + rawBody)` в hex. Срок подписи 5 минут. Намерение создаётся авторизованным клиентом через `/api/ads/begin` на 15 минут. Проверка подлинности рекламного события должна происходить **до** подписания адаптером. Секрет не передаётся в браузер.

## Запуск и проверки

Нужен Node.js 24.22.1 или новее в ветке 24. Runtime не требует npm-зависимостей.

Из корня репозитория:

```sh
node telegram/build.cjs
node --test telegram/tests/*.test.cjs tests/p2p-routing-baseline.cjs
node --require ./telegram/tests/release-preload.cjs --test packaging/test-dice.cjs online/construction.test.cjs online/public.test.cjs
```

Оригинальные тесты используют Telegram-сборку через test-only preload. Код приложения не имеет тестового входа или обхода проверки `initData`.

Браузерная проверка требует Playwright 1.62.1 и Chromium. Установить в `telegram/`: `npm install --no-save playwright@1.62.1`, затем `npx playwright install chromium`. Из корня выполнить `node telegram/tests/browser-smoke.cjs`. Для установленного Chrome можно задать `QA_CHROME` с абсолютным путём к исполняемому файлу. Telegram-host в этом тесте имитируется; тест не совершает реальных платежей и не показывает настоящую рекламу.

Скопировать `.env.example` в `.env` внутри `telegram/`, заполнить приватно. Секреты создать локально командой `node setup-bot.cjs --secrets`; не публиковать вывод. Из `telegram/` запустить:

```sh
node --env-file=.env server.cjs
```

Базу и `.env` нельзя коммитить. Не использовать реальный токен в публичных CI-логах. Не размещать Mini App под origin исходной PWA: её service worker может перехватывать запросы. Нужен отдельный HTTPS-origin; пример Caddy — `Caddyfile.example`.

## Развёртывание владельцем

1. Выделить отдельный HTTPS-домен и Telegram-бота. Указать `PUBLIC_ORIGIN`, `TELEGRAM_BOT_TOKEN`, длинный независимый `TELEGRAM_WEBHOOK_SECRET`, настоящий `SUPPORT_CONTACT`.
2. Развернуть отдельный сервис и постоянный диск для `telegram.sqlite` и `rooms.sqlite`; исходный сервер игры не заменять. Docker из корня: `docker build -f telegram/Dockerfile -t manager-telegram .`. Передавать `.env` через окружение; volume `/data` должен быть доступен пользователю `node` (UID 1000).
3. Проверить HTTPS `/health`. В BotFather настроить Main Mini App и домен. Подготовленный инструмент `node --env-file=.env setup-bot.cjs` проверяет настройки без изменения бота. **Только после разрешения владельца** добавить `--apply`: это установит webhook, кнопку приложения и команду `/paysupport`. Скрипт не запускался с `--apply` при разработке.
4. Проверить авторизацию и восстановление профиля на двух настоящих устройствах; проверить Android, iOS, Desktop и Web. Добавить проверку шестиместной игры, отключений и возвращения.
5. Сначала проверить Stars в тестовой среде Telegram. Затем отдельно разрешить реальные платежи и проверить покупку/отмену/возврат. Возвраты выполнять официальным `refundStarPayment`; бот обработает `refunded_payment`. Автоматического списания и подписок нет.
6. Подключить AdsGram-площадку и Reward Block ID, получить проверяемые серверные события, реализовать и проверить адаптер. До этого оставить рекламные награды выключенными.
7. Настроить ежедневные резервные копии обеих баз и хранение вне сервера. Скрипт `backup.cjs` использует SQLite backup API и проверяет целостность; задать `TELEGRAM_DATABASE` и `BACKUP_DIRECTORY`. Выполнить отдельно для базы покупок и базы комнат. Проверить восстановление на отдельном экземпляре перед запуском.

Реальные устройства, настоящая реклама, настоящие платежи, возвраты провайдера и production-домен при разработке не проверялись. Критерии полного production-запуска ещё не выполнены.
