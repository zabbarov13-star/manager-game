Производительность: последовательный прогон Миры в настольном Chrome после исправления планировщика — около 30 кадров/с, p95 интервала около 33,5 мс вместо прежних ~50 мс. Результаты сохранены в representative внутри playback.json. Стресс с 12 одновременно отрисовываемыми и считываемыми Canvas может давать заметные задержки; это диагностический режим, не доказательство плавности телефонов. Декодирование уже встроенных в демо WebP и CPU-замер кадра не измеряют сетевую загрузку реального Telegram-клиента.

## Конкретные действия владельца

1. Подтвердить доступ к существующему VPS: SSH-пользователь с sudo и локальный ключ/agent либо приватный inventory по deploy/README.md. Не присылать ключи/пароли в чат. Бот, токен, SUPPORT_CONTACT и настройки владельца уже есть локально; не создавать ещё одного бота до проверки среды.
2. По inventory согласовать обновление исходной установки, origin и проверяемую копию всех данных. Старый Manager уже найден публично; автоматически дублировать или перенастраивать его нельзя. deploy/ACCESS-STATUS.md содержит факты, риски и границы подготовки.
3. Настроить Main Mini App нового бота на публичный тестовый адрес; dry-run/setup — пошагово в RELEASE-RUNBOOK.md.
4. Пройти официальный тестовый цикл Stars на новом боте с STARS_ENABLED=1. До него магазин выключен; реальные Stars без отдельного разрешения не трогаются. Подготовить условия покупок и поддержку перед публичным выпуском.
5. Зарегистрировать AdsGram Test Platform/Reward Block, сохранить Block ID, запросить доверенное серверное подтверждение по готовому тексту ADSGRAM-INTEGRATION.md. Один только Block ID не позволяет безопасно включить выдачу.
6. Выполнить ручную приёмку на Android/iOS и втором подключении; при необходимости предоставить TURN. Просмотреть демо 12 героев и отметить художественные замечания.
7. После закрытия этих пунктов отдельно разрешить публикацию/настройку production и реальные финансовые проверки. PR не сливается автоматически.
