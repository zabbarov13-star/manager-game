# Отдельный публичный тест на alwaysdata Free

Решение для личного некоммерческого теста. Площадка указывает 0 €/месяц, SSD 1 ГБ, 256 МБ RAM, ¼ CPU, три дня резервных копий и адрес alwaysdata.net. Node.js 24 поддерживается. При отсутствии карты аккаунт остаётся в ограниченном режиме с более строгой обработкой HTTP. Конкретные лимиты запросов и исходящего трафика, поведение после простоя и срок запуска этого приложения ещё требуется проверить на реальном аккаунте. Тариф не следует считать гарантией круглосуточной работы или доступности из любой сети.

## Проверка маршрута

7 ноября 2026 г. три публичных узла Globalping из РФ получили HTTPS 200 от demo.alwaysdata.net. Узлы находились в сетях Timeweb (Москва), Selectel (Санкт-Петербург) и Yandex.Cloud (Москва). [Результаты замера](https://api.globalping.io/v1/measurements/2GU0Y2L2l0YodVYHO00021Sec). Панель admin.alwaysdata.com вернула HTTPS 302 с трёх российских узлов. [Замер панели](https://api.globalping.io/v1/measurements/2bi3ZREgsjV682iUy00021Sea).

Проверены общедоступные адреса провайдера. Для приёмки нужен отдельный адрес игры, успешный запрос /health и полный сценарий комнаты на телефоне с недоступным Render. Ни один тест этого документа не измерял доступность мобильных операторов.

## Развёртывание для администратора

Владелец открывает отдельный аккаунт Free без привязки карты. Настройка выполняется с доступом к этому аккаунту. Пароль и секреты в чат не передаются. Команды ниже предназначены для администратора развёртывания.

1. Создайте отдельный Node.js-сайт на стандартном адресе аккаунта. Команда запуска `NODEJS_VERSION=24 node manager-online/current/online/alwaysdata-start.cjs` выполняется из домашнего каталога аккаунта. Приложение слушает предоставленные площадкой IP и PORT. HTTPS завершается на прокси площадки.
2. Разрешите отдельному SSH-ключу писать в каталог manager-online. Проверьте ключ SSH-сервера по данным провайдера. Выдайте отдельный API-ключ с доступом к перезапуску тестового сайта.
3. Задайте GitHub Actions variables MANAGER_FREE_ACCOUNT, MANAGER_FREE_SSH_USER, MANAGER_FREE_SITE_ID и защищённые Secrets MANAGER_FREE_SSH_KEY, MANAGER_FREE_KNOWN_HOSTS, MANAGER_FREE_API_KEY. Включите MANAGER_FREE_HOST_ENABLED=true только после настройки отдельного аккаунта. Новый push в ветку PR № 2 с изменением online или workflow запускает установку и HTTPS-проверку конкретного коммита.
4. SQLite хранится в manager-online/data/rooms.sqlite вне папки выпуска. На этом варианте используется журнал DELETE с одним экземпляром Node. При переключении каталога current база остаётся на месте. Для отката выберите предыдущий каталог releases и перезапустите только тестовый сайт. Учитывайте квоту диска, проверяйте копии базы и удаляйте устаревшие релизы по согласованию.
5. Перед публикацией ссылки проверьте создание комнаты и вход по приглашению, несколько ходов, повтор после потери связи, перезапуск процесса с сохранением партии, отсутствие обращений к Render, HTTP 429/5xx, доступ из российских узлов и реального телефона. Для проверки лимита памяти, холодного старта и квоты диска используйте отдельную тестовую партию.

GitHub Pages продолжает обслуживать стабильную 0.19.0. Тестовый сайт имеет отдельный origin и отдельные сохранения. Этот вариант использует одну точку входа. Клиент PR поддерживает дополнительные входы к той же базе, если они появятся. Второй бесплатный публичный хост здесь не настроен.
